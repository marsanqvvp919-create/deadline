# 赤字にならない送料電卓

シンガポール・韓国 → 日本の DHL / FedEx 送料を、通常便・クール便（国内クール加算／個口）で概算する React アプリ。

## 使い方

1. 発送元（シンガポール／韓国）と 通常便／クール便 を選ぶ
2. カテゴリキー → テンキーで個数 → 「＋追加」（同じカテゴリは合算、「−」で差し引き）
3. DHL と FedEx の合計・内訳・小口数が自動で出る（最安に印）

## 計算ロジック（`src/lib/calc.js`）

- **小口判定**: 商品の実効サイズ（縦×横×高さ）の合計を、発送元ごとの箱の「外寸容積 × 充填率」で割って箱数を出す。容量で決まれば満杯の最大箱＋端数箱（入る最小サイズ）、1箱の最大重量を超えるなら重量で均等割り。シンガポール発と韓国発はフォワーダーが違うので箱と充填率を分けている
- **商品の重量・実効サイズ**: 2026年7〜10月の請求（DHL 運賃請求 279件・FedEx 関税請求 239件の課金重量）を、楽楽販売の出荷明細と追跡番号で突き合わせて逆算した値（`src/data/defaults.js`、詳細は `docs/calibration-2026-10.md`）
- **課金重量**: 箱ごとに 実重量（商品＋箱・緩衝材）と容積重量（縦×横×高さ÷容積係数）の大きい方を 0.5kg 切り上げ、全箱合計
- **国際運賃**: DHL・FedEx の2026年公開輸入料金表（日本着払い・免税）をそのまま使う（`src/data/tariffs.js`）
  - DHL Express Worldwide Import：韓国＝区分1、シンガポール＝区分3。30kg 超は 1kg ごとに加算
  - FedEx International Priority 輸入（ImportOne）：韓国＝区分A、シンガポール＝区分B。21kg 以上は kg単価 × 課金重量
- **合計**: 公開運賃 −契約割引(%) ＋ 繁忙期追加金(円/kg) ＋ 燃油サーチャージ(%・運賃と繁忙期に対して) ＋ GoGreen Plus(円/kg) ＋ 手数料(円/件) ＋（クール便なら）加算額×個口数
- **FedEx の初期値（推測）**: 運賃の請求書がないため、「FedEx の方が少し高め」という実感に合わせて代表的な荷物の合計で DHL の約1.1倍になる割引率にした（韓国発 78%引き・シンガポール発 72%引き）
- **DHL の初期値**: 2026/10/15 発行の INBOUND INVOICE（279件）の実績。公開料金の80%引き、GoGreen Plus 65円/kg、シンガポール発は輸出申告料 1,800円/件
- 関税・輸入消費税は含まない

燃油サーチャージは毎週変わる。「マスタ設定」で公式サイトの最新値に更新する。契約割引がある場合は割引率を入れる。
料金表が改定されたら `src/data/tariffs.js` を差し替える。

## マスタの保存

マスタはブラウザの localStorage に保存される。別のPC・スタッフと揃えるときは「JSONを書き出す」→ 相手の画面で「JSONを読み込む」。
全員で常に同じマスタを共有したい場合は、Supabase などのデータベースに置き換える。

## 開発

```bash
npm install
npm run dev    # http://localhost:5173
npm test       # 計算ロジックのテスト
npm run build
```

## Vercel へのデプロイ

1. GitHub に新しいリポジトリを作って push
2. Vercel → Add New → Project → そのリポジトリを Import
3. Framework Preset は自動で **Vite** になる（Build: `npm run build` / Output: `dist`）。そのまま Deploy
